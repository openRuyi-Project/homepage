# 学生参与指南

本指南面向准备申请 openRuyi 开源之夏 (OSPP) 项目的学生，介绍从确认资格、选择项目到开发和结项的完整流程。

开始申请前，请先阅读 OSPP 官方的[学生指南](https://docs2026.summer.ospp.ac.cn/help/student%20guide)。活动规则、时间和系统要求以 OSPP 官方说明为准。

## 一、确认参与资格

申请前确认自己符合以下条件:

- 年满 18 周岁，并且是高校在校学生。
- 在所申请项目的整个开发周期内保持在校学生状态。
- 已获得硕士或博士研究生录取资格但尚未入学的，能够提供录取通知书及相关说明材料。
- 不同时以学生和导师两种身份参加本届活动。
- 同一时间只申请或承担一个项目；申请落选或当前项目结项后，才可以申请其他项目。

中国籍学生需要准备有效身份证件和学籍证明；外籍学生需要准备护照及能够显示预计毕业时间的学生证、录取通知书或在读证明。具体材料要求请查看 OSPP 官方学生指南。

## 二、选择参与模式

### 经典模式

经典模式适合希望从明确任务开始参与的学生:

1. 打开 [openRuyi 的 OSPP 组织页面](https://summer.ospp.ac.cn/org/orgdetail/59ab01aa-4c76-4f61-834f-ac4c636267bf)，查看已经发布的项目。
2. 阅读项目描述、技术要求、预期成果、开发周期和成果仓库。
3. 查看成果仓库的 README、贡献指南、Issue 和相关代码，确认自己理解项目背景。
4. 通过项目详情页中的导师邮箱联系导师，沟通项目范围、实现思路和申请计划。
5. 在 OSPP 系统中提交项目申请书。

### 领航模式

领航模式适合希望围绕社区需求提出具体问题和解决方案的学生:

1. 在 OSPP 官网查看领航模式需求方向，选择与自己能力和兴趣匹配的方向。
2. 深入了解社区和相关仓库，明确需求对应的实际问题。
3. 按照社区指定的渠道提交简易提案，并参加社区组织的提案沟通。
4. 提案入选后，与导师共同细化需求、开发计划和预期成果。
5. 社区在 OSPP 系统中创建对应项目后，学生再提交正式项目申请书。

领航模式的提案、Pitch 和项目生成方式与经典模式不同。准备提案前，请完整阅读 OSPP 官方的[领航模式指南](https://docs2026.summer.ospp.ac.cn/help/Pioneer-guide)。

## 三、申请前做好准备

项目申请不要求学生已经拥有丰富的开源经验，但需要证明自己理解项目并具备完成计划的基础。建议按以下顺序准备:

1. 阅读项目仓库的 README、贡献指南、开发文档和开源协议。
2. 搭建开发环境，确认能够构建、运行或测试现有项目。
3. 梳理项目目标、当前实现、待解决问题和验收方式。
4. 与导师沟通自己的理解、技术方案、开发计划和风险。
5. 根据沟通结果完善申请书，使每一项计划都有明确产出和检查方式。

申请期间可以正常参与 openRuyi 社区贡献，但不得提前实施申请书中约定的 OSPP 项目工作。中选结果公布前完成的相关开发和提交，不计入项目结项成果。

## 四、注册并提交申请

### 1. 注册学生账号

从[开源之夏官网](https://summer.ospp.ac.cn/)进入学生登录入口，注册账号并提交个人资料。往届学生可以使用原账号登录，但需要更新个人信息并重新报名。

用于提交项目成果的 Git 账号必须公开，账号的公开邮箱必须与报名资料中填写的 Git 邮箱一致。注册后应先检查账号和邮箱设置，避免在结项时无法确认成果归属。

### 2. 编写申请书

根据项目要求，参考[项目申请模板](https://docs2026.summer.ospp.ac.cn/upload/申请材料模板.pdf)准备相关材料。

申请书质量是导师和组委会审核的重要依据。可以参考 OSPP 官方的[项目申请教程](https://docs2026.summer.ospp.ac.cn/help/student%20application%20advice)，但应根据实际项目独立完成内容，不要照搬示例。

### 3. 提交申请

在项目上线后，通过 OSPP 系统提交申请材料。提交前再次确认:

- 申请的是正确的 openRuyi 项目和参与模式。
- 所选开发周期内自己始终保持在校状态。
- 申请书中的目标、计划和成果与项目详情一致。
- Git 账号公开邮箱与报名资料中的 Git 邮箱一致。
- 当前没有同时申请或承担其他 OSPP 项目。

导师审核后，申请还需要经过组委会审核。中选结果可在 OSPP 官网、系统和通知邮件中查看。

## 五、中选后开始开发

中选后应在三日内登录 OSPP 系统签署劳务协议。逾期未完成签署可能影响后续参与，请及时查看系统和报名邮箱中的通知。

项目开发期间:

1. 以项目详情页标明的开发周期为准，不提前开始，也不要擅自改变项目范围。
2. 使用项目详情页指定的成果仓库开发和提交代码。
3. 按申请书中的计划推进任务，并建议每周与导师沟通一至两次。
4. 及时同步进度、遇到的问题、方案调整和阶段成果。
5. 独立完成项目开发和 PR/MR；导师负责提供方向性指导，不代替学生提交或修改成果。
6. 对功能和修复编写可重现的测试，并同步完善使用、开发或维护文档。

如果实际开发与计划出现明显偏差，应尽早和导师讨论调整方案。因特殊原因无法继续时，需要向导师、社区和组委会申请终止项目；不要直接失联或无故退出。

## 六、提交成果并完成结项

在项目开发周期结束前，学生需要:

1. 向指定成果仓库提交由本人完成的 PR/MR。
2. 在 OSPP 系统中填写 PR/MR 链接。
3. 按官方模板完成并上传结项报告。

结项报告应清楚说明:

- 已完成的工作、实现方案和成果进度。
- 项目目标与实际产出的对应关系。
- 遇到的问题、解决过程和个人总结。
- 测试用例、测试环境和验证结果。
- 成果的应用、发布及后续维护计划。

开发期结束后进入 PR/MR 完善和合入阶段。此阶段可以继续修改已经提交的 PR/MR，但新增 PR/MR 不计入项目成果；项目结项时间以成果最终合入的时间为准。

导师和组委会将综合检查项目完成度、学生参与度、代码贡献量与质量、测试和文档、成果应用情况等内容。通过结项考核的学生可获得结项证书和相应劳务报酬，并有机会参加优秀学生评选。

## 七、快速检查清单

### 提交申请前

- 已确认年龄、学籍和项目开发周期符合要求。
- 已阅读 OSPP 官方学生指南和学生参与协议。
- 已确认参加经典模式还是领航模式。
- 已阅读项目仓库文档并完成基础环境验证。
- 已与导师沟通项目范围、方案、计划和预期成果。
- Git 账号公开邮箱与报名资料中的 Git 邮箱一致。
- 申请书包含明确的里程碑、成果和验收方式。

### 中选后

- 已在中选后三日内签署劳务协议。
- 已按计划与导师保持沟通并记录阶段成果。
- 已由本人向指定仓库提交 PR/MR。
- 已完成测试、文档和结项报告。
- 已在开发周期结束前向系统提交 PR/MR 链接和结项报告。
- 已跟进现有 PR/MR，直至成果合入。
