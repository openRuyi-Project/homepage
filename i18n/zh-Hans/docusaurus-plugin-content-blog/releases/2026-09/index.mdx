## RVA23：完善构建、数据面与容器支持

本版本的 RVA23 改进覆盖三个方面：BCLR 代码生成修正、基于 RVV 的数据面路径，以及容器硬件探测。
编译侧修正了会破坏正确性的BCLR 代码生成问题，运行时侧 OpenJDK 与 DPDK 走向量优化路径；
容器侧放行 riscv_hwprobe 后，容器内程序得以读取真实 CPU 能力并选择对应优化分支。

### 容器硬件探测：SpacemiT V100 实测

在 SpacemiT V100（RVA23）容器内实测：放行 riscv_hwprobe 后，OpenSSL 3.6.3 识别并启用 Zvkned / Zvknhb / Zvksed 等向量密码扩展，zlib-ng 启用 Zbc 加速的 crc32。已验证 openssl、python3 zlib、pigz.

## Ceph 与 SPDK：块存储与用户态存储后端扩展

SPDK 可直接对接本地 io_uring 与 Ceph RBD 后端并启用远程管理代理；Ceph 的服务账户、mgr 模块与 CephFS 组件可用。

### SPDK（25.09，启用 --with-uring --with-rbd --with-sma）
- 新增 io_uring bdev 模块（本地异步块设备）。
- 新增 Ceph RBD bdev 模块（对接 Ceph 后端）。
- 启用 SMA（Storage Management Agent，远程存储管理）。
- 修复 spdk-tools 依赖：新增 python-configshell-fb，python-grpcio-tools 升级至 1.82.1 以匹配 protobuf 7。

### Ceph（21.3.0+git20260917.35ae586）更新至上游 main 分支开发快照（v21.3.0-3295-g35ae586）
- 改用 systemd-sysusers 创建 ceph、cephadm 用户；原 %pre 调用 shadow 的 useradd 未声明依赖，导致 /var/lib/ceph 归属 root。
- 为 mgr 模块补充 cherrypy、pyyaml，使 prometheus 模块可启用。
- 回移 `ceph-fuse@.service`、`cephfs-shell`、`ceph-crash` 修复。

### 在 SpacemiT V100（RVA23）上以 3 mon / 9 OSD（NVMe）三副本集群实测：
- RBD（librbd / krbd / rbd-nbd）、CephFS（内核与 FUSE 客户端、快照、配额、subvolume）、RGW（S3 multipart / versioning / lifecycle）功能验证通过。
- 纠删码 isa / jerasure / clay 与 snappy / zstd / lz4 / zlib 压缩可用。
- mgr 常用模块可启用，prometheus 与 ceph-exporter 导出指标，监控通过 CLI 与 Prometheus 提供；cephadm 可单机 bootstrap 并管理 mon / mgr。
- SPDK io_uring bdev 与 RBD bdev 在 RISC-V 上跑通；SMA gRPC 接口（设备创建、卷挂载、QoS）验证可用。

- openruyi-minimal 将 gnupg 加入推荐依赖。
