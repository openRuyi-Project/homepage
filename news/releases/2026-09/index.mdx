We are pleased to announce the September 2026 release of openRuyi. This release improves RVA23 support, expands the cloud and storage software stacks, upgrades the Go 1.27 build environment, and ships a batch of security updates.

## RVA23: Improving Build, Data Plane, and Container Support

The RVA23 improvements in this release cover three areas: BCLR code generation fixes, RVV-based data-plane paths, and container hardware probing. On the compilation side, the release fixes a BCLR code generation problem that could break correctness. On the runtime side, OpenJDK and DPDK gain vectorized optimization paths. On the container side, allowing `riscv_hwprobe` lets programs inside containers read real CPU capabilities and choose the matching optimization branch.

### Compilers and Data Plane

| Component (Version) | September Change | User Problem Solved |
|---------------------|------------------|---------------------|
| GCC 16 (16.2.0) | Backports upstream BCLR fixes and fixes RISC-V BCLR sign extension | When compiling with the `zbb,zbs` extensions, GCC 16 optimizes the code to include the `bclr` instruction. Because `bclr` does not keep a 32-bit value sign-extended, loops such as `m &= m - 1` fail to terminate, and DPDK hangs in `rte_softrss()`. On RVA23 with an AMD GPU, the GCC 16 RISC-V backend `bclr_lowest_set_bit` miscompiles a bit-traversal loop in the Mesa ACO ILP scheduler, which finally reads a null pointer and raises SIGSEGV, making the graphics stack unusable |
| DPDK (25.07) | Builds on RVA23 with `-Dcpu_instruction_set=rva23u64` to enable vector paths; patches cover RISC-V vector implementations of lpm lookup, fib lookup, node lookup, and ACL | The lpm, fib, acl, and node lookup paths gain RVV implementations |
| DPDK (25.07) | Links against libarchive so the EAL can load compressed firmware | The E810 DDP package ships as `ice.pkg.xz`, which `rte_firmware_read()` previously could not decompress, so ice PMD probing failed |
| containers-common (0.67.0) | The default seccomp profile allows `riscv_hwprobe` | OpenSSL inside containers can recognize vector and vector-crypto extensions, and zlib-ng can enable the Zbc-accelerated crc32 |
| OpenJDK | Merges 15 RISC-V patches: Zbs / Zfa instruction generation, RVV vset state optimization, CRC32C intrinsic, and slicing-by-8 CRC32 | Adds instruction support for RVA23 and optimizes the CRC32 and vector state handling paths |
| linux / linux-lts | 7.2.6 / 6.18.54, with refreshed patchsets and configs | Tracks the upstream stable releases |

### Container Hardware Probing: Measured on SpacemiT V100

Measured inside a container on SpacemiT V100 (RVA23): after allowing `riscv_hwprobe`, OpenSSL 3.6.3 recognizes and enables vector-crypto extensions such as Zvkned, Zvknhb, and Zvksed, and zlib-ng enables the Zbc-accelerated crc32. Verified with openssl, python3 zlib, and pigz.

## Ceph and SPDK: Block Storage and User-Space Storage Backends

SPDK can directly attach to local io_uring and Ceph RBD backends and enables a remote management agent; Ceph service accounts, mgr modules, and CephFS components are available.

### SPDK (25.09, enabling --with-uring --with-rbd --with-sma)

- Adds an io_uring bdev module (local asynchronous block device).
- Adds a Ceph RBD bdev module (attaching to Ceph backends).
- Enables SMA (Storage Management Agent, remote storage management).
- Fixes spdk-tools dependencies: adds python-configshell-fb and upgrades python-grpcio-tools to 1.82.1 to match protobuf 7.

### Ceph (21.3.0+git20260917.35ae586), updated to an upstream main-branch development snapshot (v21.3.0-3295-g35ae586)

- Switches to `systemd-sysusers` to create the ceph and cephadm users; the previous `%pre` called shadow's `useradd` without declaring the dependency, which left `/var/lib/ceph` owned by root.
- Adds cherrypy and pyyaml for mgr modules, so the prometheus module can be enabled.
- Backports fixes for `ceph-fuse@.service`, cephfs-shell, and ceph-crash.

### Measured on SpacemiT V100 (RVA23) with a 3-mon / 9-OSD (NVMe) three-replica cluster

- RBD (librbd / krbd / rbd-nbd), CephFS (kernel and FUSE clients, snapshots, quotas, subvolumes), and RGW (S3 multipart / versioning / lifecycle) all passed functional verification.
- Erasure coding isa / jerasure / clay and snappy / zstd / lz4 / zlib compression are available.
- Common mgr modules can be enabled; prometheus and ceph-exporter export metrics, and monitoring is provided through the CLI and Prometheus; cephadm can bootstrap a single node and manage mon / mgr.
- SPDK io_uring bdev and RBD bdev run on RISC-V; the SMA gRPC interface (device creation, volume attachment, QoS) is verified as usable.

## Graphics Stack: NVK Included in the Build, Vulkan SDK Unified at 1.4.357.0

NVK, the open-source NVIDIA Vulkan driver, is included in the build for the first time.

- Mesa 26.2.2, with NVK included in the build (`-Dvulkan-drivers=...,nouveau`). NVK is produced together with mesa-vulkan-drivers. Hardware runtime and CTS verification will follow in a later release.
- Nine Vulkan SDK components are upgraded to 1.4.357.0 in unison.
- Adds vkmark: a lightweight Vulkan benchmark suite supporting X11, Wayland, KMS, direct display, and headless modes; backports a lavapipe crash fix.
- glmark2 enables GBM variants (headless/DRM scenarios); adds assimp and glm (3D graphics development).
- Qt 6 Base enables the Accessibility API.

## Software Supply Chain: Repository GPG Signature Verification and Security Updates

Packages in the repository enable GPG verification by default, so the install and upgrade paths can validate signatures; affected packages moved to upstream versions that contain the fixes.

- openruyi-repos ships `RPM-GPG-KEY-openruyi` and `RPM-GPG-KEY-openruyi-obs`, and writes `gpgcheck=1` and `gpgkey=file://.../RPM-GPG-KEY-openruyi*` into the repo file.
- rpm adds a gnupg runtime dependency.
- openruyi-minimal adds gnupg to its recommended dependencies.
